# Competition handoff — Lunar Landing Site Navigator v1.3.3

**Team: Astralis · Release prepared by Deb · November 15, 2026**

This is a handoff checklist, not a claim that the project has been submitted, accepted, or certified for mission operations. Use the [handbook](../ASTRALIS-HANDBOOK.md), [rubric summary](../JUDGING-RUBRIC.md), and [source register](../REFERENCES.md).

## What to demonstrate

| Challenge capability | Where to show it |
| --- | --- |
| Select and compare sites | Named-site catalog, feature search, custom map coordinate, and three-scenario comparison with editable sites and dates. |
| Change landing date and duration | Mission setup and shared timeline; full-year exploration within 2024–2030 data coverage. |
| Sun and Earth relative to a local horizon | Surface sky plot and first-person view, position annotations, and estimated next rise/set. |
| Assess solar and communications opportunities | Energy, average power, sunlight/Earth-view hours and percentages, overlap, and longest gaps. |
| Explore space and terrain | Orbit → Moon Map → Surface in one viewer; analysis-layer controls and measured terrain where available. |
| Understand changes with time | Timeline playback and manual scrubbing; moving light and modeled crater shadows. |
| Compare South Pole options | Editable slope screen and communication, solar-energy, and balanced ranking scenarios. |
| Explain the result to a new user | Guided examples, plain-language units, visible source captions, and expandable method details. |

## Evidence for the five rubric categories

| Criterion | Evidence to prepare |
| --- | --- |
| Impact | Explain a concrete decision affected by delaying landing or changing sites. Avoid claiming the app replaces mission safety analysis. |
| Creativity | Show the shared viewer and how terrain, energy, and uninterrupted Earth visibility alter a decision. |
| Validity | Show the documented Horizons comparison, regression results, real terrain source, and limits of sampling and solar-array assumptions. |
| Relevance | Connect each output to the challenge and identify NASA data that actually drives it. |
| Presentation | Tell one short decision story, use readable units, and provide working links and clear credits. |

## Suggested demo route

1. Select a date and mission duration. State the mission objective in one sentence.
2. Open South Pole landing suggestions. Compare the leading communications, solar, and balanced options; show energy and the longest Earth-view gap.
3. Select a patch and enter Surface. Scrub time to explain a terrain shadow or visibility change. Distinguish generated foreground rocks from measured elevation.
4. Compare an alternative site or schedule. End with the decision supported by the results and the NASA/JPL/LOLA credits.

Adapt this to the final permitted demo duration. Record actual displayed values from the tagged release, not invented example numbers.

- [ ] Prepare the required demo and final-project links. Test them while signed out. A private GitHub repository is accessible only to authorized accounts; its URL alone is not a public judging deliverable.
- [ ] If a public hosted demo is required, deploy and test that separately. GitHub source publication does not by itself deploy the terrain server or restore GitHub Pages.
- [ ] Include NASA data usage, the central reference link, third-party credits, and an accurate AI-assistance disclosure in the project form.
- [ ] Review code/artwork redistribution requirements and choose a team license if required. No project-wide license has been selected in this release.
- [ ] Check a named site, custom coordinate, and suggested patch on the release; test one cold start and one reduced-motion/small-screen session.
- [ ] Review resolution limits, approximate Earth rotation, center-based visibility, partial-eclipse limitations, and simplified panel assumptions. Do not describe shortlisted patches as certified safe landing sites.
- [ ] Confirm final test results and release tag. Complete the actual submission action and save its confirmation; a GitHub push is not a competition submission.
